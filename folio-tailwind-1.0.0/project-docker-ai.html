The Problem

After completing both the Docker workshop and Introduction to AI course, I noticed a common pain point in ML development: "It works on my machine" syndrome. Different Python versions, missing dependencies, and conflicting libraries make sharing ML projects nearly impossible.

I wanted to create a standardized, reproducible environment where anyone could pull my project and run the ML models without any setup friction.

The Solution

1 Dockerfile 

# Use official Python image
FROM python:3.9-slim

# Set working directory
WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y \
    gcc \
    && rm -rf /var/lib/apt/lists/*

# Copy requirements first (layer caching)
COPY requirements.txt .

# Install Python packages
RUN pip install --no-cache-dir -r requirements.txt

# Copy project files
COPY . .

# Expose port for Jupyter
EXPOSE 8888

# Run the ML script
CMD ["python", "model.py"]

2 requirements.txt 

numpy==1.24.3
pandas==2.0.3
scikit-learn==1.3.0
matplotlib==3.7.2
seaborn==0.12.2
jupyter==1.0.0

3 ML Model Script (model.py) 

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score

# Load dataset
data = pd.read_csv('data.csv')
X = data.drop('target', axis=1)
y = data['target']

# Split and train
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)
model = RandomForestClassifier(n_estimators=100)
model.fit(X_train, y_train)

# Evaluate
predictions = model.predict(X_test)
accuracy = accuracy_score(y_test, predictions)
print(f"Model Accuracy: {accuracy:.2f}")

4 Docker Commands Used 

# Build the image
docker build -t ml-environment .

# Run container with volume mount
docker run -v $(pwd)/data:/app/data -p 8888:8888 ml-environment

# Run Jupyter notebook inside container
docker run -p 8888:8888 ml-environment jupyter notebook --ip=0.0.0.0 --allow-root

# Push to Docker Hub
docker tag ml-environment username/ml-environment:latest
docker push username/ml-environment:latest

Key Features

Layer Caching

Requirements copied before source code for efficient Docker layer caching

Volume Mounting

Data directory mounted as volume for persistent storage without rebuilding

Slim Base Image

python:3.9-slim reduces image size by ~60% compared to full image

Jupyter Integration

Exposed port 8888 for interactive notebook development inside container

What I Learned

  • Containerization Principles: Understanding images vs containers, layers, and the importance of minimal base images
  • Dependency Management: Pinning exact versions in requirements.txt ensures reproducibility across environments
  • Dev/Prod Parity: Docker ensures the development environment matches production exactly
  • AI Model Deployment: Containerized ML models can be easily shared and deployed to cloud platforms
